Open #EDITORIAL-482

Refactor GraphQL Mutation logic to use standardized artisan fragment patterns

James Dalton opened this issue 3 days ago

The current implementation of our GraphQL mutations in the editorial dashboard lacks consistency. Specifically, the UpdateEditorialContent and CreateDraft mutations are using inline fields instead of our shared fragment library.

This causes maintenance overhead when updating typography tokens or color surface logic, as changes need to be mirrored across multiple files.

Proposed Changes:

  • Consolidate metadata fragments into ArtisanCoreFields.
  • Update the mutation hook to utilize Apollo's caching mechanism via standardized IDs.
  • Remove deprecated type definitions in the local mutation scope.
